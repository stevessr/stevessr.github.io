PICO 4 Ultra：SukiSU Nova 内置 DF 越狱版（DirtyFrag + KPM）

设备：PICO 4 Ultra（sparrow / A9210，OS 5.15.8，内核 5.10.198-perf-g49587cd7a509-ab176，GKI android12-5.10）。

上一篇：临时 root 记录与模块合集。这一版把整条越狱链缝进了 Nova 管理器本体——只装一个 APK，不再需要单独的 DFRoot。

内置了什么

  • DirtyFrag 利用（CVE-2026-43284）：原 DFRoot 的利用代码（libdfroot.so + libbootstrap.so）。
  • DFRoot 内核模块：8 个 KMI 的 dfroot-*.ko 内嵌，本机用 android12-5.10 重编（路径改为 Nova 包名）。
  • ksud：内嵌 KPM 版 kernelsu.ko（CONFIG_KPM=y）+ 内置 Zygisk。
  • KPM 工具：libkptools.so + kpimg（来自官方 Nova v3.0.0）。
  • 首页 “DF 越狱” 按钮：点按自动跑完整条链，页面实时显示日志（Material/Miuix 双主题）。
  • 开机自启：BootReceiver + BootService（设置里可开关）。

签名与识别

自编译管理器是 debug 签名，内核模块的 KSU_EXPECTED_SIZE=0x2e8 / KSU_EXPECTED_HASH 与之匹配，所以模块认这个管理器（is_manager: 1）。与官方 Nova 签名不同，不能覆盖安装，需先卸载官方版。

踩坑记录

  • KPM 代码过不了新 clang：5.10 内核的 u64_to_user_ptr 宏带 typecheck，对 const u64 默认初始化在 clang 19+ 是硬错误（-Wdefault-const-init-var-unsafe）。加了个绕过 typecheck 的本地转换函数。
  • dfroot.ko 必须传 CROSS_COMPILE：不传的话 clang 落到 x86_64 host target，-ffixed-x18/sysreg 全报错。
  • bootstrap 读不到 prefs：DFRoot 的 bootstrap 从 /data/user_de/0/<pkg>/shared_prefs/dfroot.xml 读 su_manager，原逻辑在 MainActivity 里写；集成版把这个初始化挪进了越狱入口。
  • 灰屏（最坑）：越狱链在 zygote 运行中 late-load 后，如果 soft_reboot=false，zygote 带着补丁过的 syscall 继续跑，fork 应用时 FD 检查直接 SIGABRT（Unable to get socket name），init 重启 zygote 又二次失败（linker 报 libnativeloader.so not found），system_server 死掉 → 灰屏。这就是 DFRoot 默认开 Auto Soft Reboot 的原因。必须让 ksud late-load 完成后走 scoped soft reboot（即之前做的保留 SurfaceFlinger/composer 的作用域重启），重启后一切正常。
  • KPM 的 .kpm 运行时加载：bridge 靠探测 __arm64_sys_truncate 是否被 kpimg 改成 supercall。boot 没刷 kpimg 补丁时返回 EOPNOTSUPP——这是 KernelPatch 设计，不是 bug。APK 内已带 kptools/kpimg，解锁 boot 后可刷补丁镜像激活。

实机验证

重启后干净状态 → 触发 DF 越狱：
  su -c id → uid=0(root) context=u:r:ksu:s0
  内核日志 is_manager: 1
  ksud 3.0.0 (uapi: 6)，kpm load/list/control 子命令可用
  软重启后 zygote 崩溃 0 次，system_server 正常
